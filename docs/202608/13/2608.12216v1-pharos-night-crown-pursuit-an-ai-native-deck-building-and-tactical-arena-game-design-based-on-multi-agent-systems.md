## 摘要
随着生成式AI技术的进步，越来越多的研究者开始探索AI原生游戏，即游戏规则直接由生成式AI驱动。本文介绍了《法罗斯之夜：王冠追猎》，一款基于多智能体系统的AI原生卡组构筑与战术竞技场游戏。该游戏使用大语言模型生成材料和卡牌、支持NPC决策，并协调自然语言交互。在游戏过程中，玩家收集材料、用自然语言描述期望的卡牌效果，并选择在竞技场中与NPC谈判或战斗。为约束模型生成的结果，系统将响应解析为结构化JSON，根据预定义机制构建卡牌效果，并将定性效果等级映射到设计者指定的数值。一项有13名参与者的小规模试玩表明，该系统能够提供具有战略意义且引人入胜的AI驱动玩法，同时也揭示了在可预测性、透明度和玩家控制方面的挑战。本工作展示了多智能体生成式AI系统在创造更具涌现性数字游戏体验方面的潜力。

## Abstract
With advancements in generative AI technology, an increasing number of researchers have begun exploring AI-native games in which gameplay rules are directly driven by generative AI. This paper presents "Pharos Night: Crown Pursuit," an AI-native deck-building and tactical arena game based on a multi-agent system. The game uses large language models to generate materials and cards, support NPC decision-making, and mediate natural-language interactions. During play, players collect materials, describe desired card effects in natural language, and choose whether to negotiate or fight with NPCs in the arena. To constrain model-generated outcomes, the system parses responses as structured JSON, constructs card effects from predefined mechanics, and maps qualitative effect levels to designer-specified numerical values. A small-scale playtest with 13 participants suggests that the system can provide strategically meaningful and engaging AI-driven gameplay, while also revealing challenges related to predictability, transparency, and player control. This work demonstrates the potential of multi-agent generative AI systems for creating more emergent digital game experiences.

## 2. 论文提出的方法论

### 2.1 核心思想

- 将卡组构筑从“选择预定义卡牌”转变为**开放式合成过程**：玩家收集 AI 生成的材料，并用自然语言“咒语”描述想要的卡牌效果，由 LLM 生成新卡牌。
- 让 NPC 成为**社交与策略智能体**：NPC 可以探索世界、谈判、交易、战斗，并通过自然语言与玩家互动，其行为由 LLM 驱动并存储记忆。
- 在保留 AI 生成灵活性的同时，通过**结构化输出和数值映射机制**约束模型结果，保证游戏平衡和可玩性。

### 2.2 关键技术细节

- **开发环境**：使用 Unity 开发；LLM 采用智谱 ChatGLM 系列模型。
- **请求队列**：为避免模型并发调用过载，系统实现请求队列，最多允许 3 个同时进行的大模型调用，其他请求排队等待。
- **智能 NPC 系统架构**：遵循“感知—思考—决策—行动”流程。
  - 默认状态为加权漫游（优先探索未到达区域），每 5 秒调用一次 LLM 进行思考。
  - 外部对象（玩家或其他 NPC 发起的交互）会中断漫游状态，NPC 转向等待外部动作并做出决策。
  - 感知器中的特殊检测（宝箱、角色、怪物等）也会中断漫游，NPC 读取世界信息后进一步决策或行动。
  - 行动执行完毕后回到漫游模式，形成循环，使 NPC 具备独立记忆和特征行为。
- **卡牌与自由合成系统**：
  - 合成流程包括**信息整合、JSON 生成与解析、数值翻译、战斗执行**四个阶段。
  - Unity 客户端将输出规范、元机制列表、放置的道具资产、玩家输入的咒语四类信息整合为 prompt，发送给 LLM 生成 JSON。
  - LLM 设计卡牌时必须从元机制列表中选择并组合“预执行条件”“预执行动作”“主要动作”“触发条件”“触发动作”等元素。
  - 返回的 JSON 在 Unity 中解析并存储到新卡牌对象的变量中。
  - LLM 不直接生成具体数值，而是生成五级定性描述（如“低”“中”），由设计者预先为每个元机制定义各等级对应的具体数值，再通过数值翻译函数映射到卡牌变量。
  - 战斗阶段卡牌按三阶段执行：评估预执行条件并执行相关动作 → 执行主要动作机制 → 评估触发条件并执行相应动作。

### 2.3 算法/流程概述

- **核心循环**：玩家探索场景收集材料 → 通过合成系统用材料和自然语言咒语生成卡牌 → 面对 NPC 时选择战斗、谈判或其他交流 → 战斗中双方按顺序自动执行卡牌 → 淘汰或存活至最后获胜。
- **卡牌生成流程**：信息整合 → LLM 生成结构化 JSON → Unity 解析 → 定性等级到数值的映射 → 战斗阶段顺序执行。
