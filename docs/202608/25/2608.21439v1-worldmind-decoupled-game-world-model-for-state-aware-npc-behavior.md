## 摘要
游戏世界模型近期在生成视觉连贯且动作可控的游戏视频方面展现出良好能力。然而，现有模型中的非玩家角色（NPC）行为要么与视频生成隐式纠缠，要么通过外部控制信号显式规定。因此，游戏世界模型必须同时理解状态、规划 NPC 的响应并渲染其视觉结果，这限制了其产生响应式且状态感知的 NPC 行为的能力。挑战在于缺乏用于基于状态的决策的显式接口。为此，我们提出了 WorldMind，据我们所知，这是游戏世界模型中第一个面向状态感知 NPC 行为的解耦框架。WorldMind 将交互式世界建模分为四个层：理解层从生成帧构建紧凑状态；决策层对紧凑状态进行推理以规划 NPC 的下一步动作；控制层将动作转换为时间对齐的条件；生成层合成其视觉结果。通过在闭环交互中重新连接各层，WorldMind 使 NPC 行为基于不断演变的游戏状态。我们进一步引入了 BOSS-140K 数据集，该数据集包含与丰富内部游戏状态配对的游戏视频，以及一个可大规模自动化采集的智能体。在 BOSS-140K 上的实验证明了可靠的紧凑状态重建和基于游戏机制的规划，在约 70% 的成对比较中，WorldMind 因其更具战术合理性且连贯的 NPC 行为而优于基线。项目主页：https://teawhite.cn/worldmind_projectpage/

## Abstract
Game world models have recently demonstrated promising capabilities in generating visually coherent and action-controllable gameplay videos. However, non-player character (NPC) behavior in existing models is either implicitly entangled with video generation or explicitly prescribed through external control signals. Consequently, a game world model has to jointly understand the state, plan the NPC's response and render its visual outcome, limiting its ability to produce responsive and state-aware NPC behavior. The challenge lies in the lack of an explicit interface for state-grounded decision-making. To this end, we introduce WorldMind, to our knowledge the first decoupled framework for state-aware NPC behavior in game world models. WorldMind separates interactive world modeling into four layers: an Understanding Layer that constructs a compact state from generated frames; a Decision Layer that reasons over the compact state to plan the NPC's next action; a Control Layer that translates the actions into temporally aligned conditions; and a Generation Layer that synthesizes their visual outcomes. By reconnecting layers in a closed interaction loop, WorldMind grounds NPC behavior in the evolving game state. We further introduce BOSS-140K, a dataset of gameplay videos paired with rich internal game states, together with an agent that automates the collection at scale. Experiments on BOSS-140K demonstrate reliable compact state reconstruction and mechanics-grounded planning, with WorldMind preferred over the baselines in approximately 70% of pairwise comparisons for its more tactically appropriate and coherent NPC behavior. - **核心问题**：现有游戏世界模型中，NPC 行为要么**隐式地**从视频生成过程中涌现，要么通过**外部控制信号显式指定**，二者都缺少一个“基于当前游戏状态进行决策”的显式接口。
  - 隐式方式：视频生成模型必须同时完成状态理解、NPC 决策和视觉渲染，多个功能在表示和时间尺度上不同，耦合在一起限制了 NPC 行为的响应性。
  - 显式方式：NPC 动作由世界模型外部给出，未将决策建立在不断演化的内部游戏状态上。
- **整体含义**：论文提出 **WorldMind**，据作者称是首个面向游戏世界模型中状态感知 NPC 行为的**解耦框架**，将状态重建、决策、动作控制和视觉生成分离，并通过闭环交互重新连接，使 NPC 行为真正基于演化中的游戏状态。

## 2. 论文提出的方法论

### 2.1 整体框架：四层解耦结构

WorldMind 将交互式世界建模分解为四个层次，并通过闭环连接：

- **L1 理解层（Understanding Layer）**：从生成帧和动作历史构造紧凑状态。
- **L2 决策层（Decision Layer）**：基于紧凑状态和技能机制推理 NPC 下一步动作。
- **L3 控制层（Control Layer）**：将实体动作转换为时间对齐的条件提示序列。
- **L4 生成层（Generation Layer）**：基于条件提示合成视觉结果，生成帧反馈回 L1，形成闭环。

### 2.2 L1：理解层——紧凑状态构建

- **游戏状态定义**：包括实体属性、动作历史、技能可用性、空间关系、战斗阶段和环境上下文。
- **技能分支（Skill Branch）**：
  - 由 NPC 动作历史确定性推导技能历史变量：上一技能、每技能冷却状态、距上次使用的时间。
  - 推理时无需引擎状态。
- **几何分支（Geometry Branch）**：
  - 从因果窗口的生成 RGB 帧中推断 boss 与玩家的距离、相对角度、朝向等。
  - 使用共享卷积编码器（ResNet-18）提取每帧特征，单层 GRU 聚合时间信息，结合 boss 身份嵌入，预测离散化和连续化的几何属性。
  - 训练使用引擎标注，推理只用 RGB 帧和 boss 身份。
- **紧凑状态**：从两个分支中选择最具决策相关性的变量，加上 boss 身份 \(id_b\)，形成：
  \[
  s_t = (id_b, e^c_t, e^g_t)
  \]
  其中 \(e^c_t\) 和 \(e^g_t\) 分别为选定的技能历史和几何变量。

### 2.3 L2：决策层——基于紧凑状态和技能机制的规划

- 使用通用大语言模型 **Gemma-4-E2B-it**，不对 BOSS-140K 进行微调，以避免直接模仿数据动作分布。
- 输入：
  - 紧凑状态 \(s_t\)；
  - boss 技能集 \(S_t\)，每个技能带自然语言机制描述和冷却信息。
- 输出：
  - **Direct Control（直接控制）**模式下，只返回 boss 计划 \(p^b_t\) 和可选理由 \(r_t\)；
  - **Director Control（导演控制）**模式下，还根据高层指令 \(d\) 返回玩家计划 \(p^p_t\)。
- 计划形式为：
  \[
  p^b_t = (a^{b,(1)}_{t}, \dots, a^{b,(H_t)}_{t})
  \]
  每个完整 boss 动作 \(a^{b,(j)}_{t}\) 包含一个技能 \(\ell^{(j)}_{t}\) 和移动指令；执行时长由确定性函数 \(D_{dur}(\ell^{(j)}_{t})\) 附加。
- 提出计划后，用冷却状态的副本进行合法性检查，移除不能合法执行的技能。
- 采用**滚动时域策略**：只把第一个动作传给 L3，其余动作视为临时计划。

### 2.4 L3：控制层——动作到时间对齐提示

- **自然语言动作接口**：每个实体在每个时间槽使用一个结构化的“[ACTION] while [MOVEMENT]”短语，区分技能执行和移动两个控制维度。
- **时间对齐**：将每个完整动作的固定执行时长转换为对应数量的 L4 时间槽，并在该区间重复动作-移动短语；每个槽将玩家和 boss 短语配对为一个复合提示序列。
- **直接控制**：用户通过键盘鼠标输入控制玩家；键盘/鼠标事件映射为玩家动作和移动短语，与 boss 短语配对。
- **导演控制**：用户提供高层自然语言指令（如“玩家持续闪避，boss 保持高度进攻性”），由 L2 决策玩家和 boss 计划，L3 同样做时间投影和复合提示。

### 2.5 L4：生成层——实时视觉合成

- **基础模型**：使用 **Wan 2.2 TI2V-5B** 并在 BOSS-140K 上端到端微调：
  - batch size = 16；
  - 训练步数 = 70k；
  - 数据预处理时将帧对齐的玩家和 boss 动作转换为与 L3 相同的条件序列格式。
- **蒸馏加速**：采用三阶段 Causal Forcing 流程，将双向模型蒸馏为少量步骤的因果自回归生成器：
  - 因果 AR 扩散教师训练；
  - 因果一致性蒸馏初始化；
  - 非对称 DMD。
- 最终蒸馏生成器运行速度约 **20 FPS**，支持实时交互。

### 2.6 BOSS-140K 数据集

- 全称：**Boss-fight Observations with States and Skills**。
- 规模：**144,631 个视频片段**，总计超过 **200 小时**，来自 **14 个 boss**，覆盖 **Game A**、**Hollow Knight** 和 **The Binding of Isaac** 三款游戏，包含 2.5D 和 2D 视角。
- 数据内容：游戏视频、帧对齐的玩家控制、boss 技能、动画状态、丰富引擎变量和自然语言描述。
- 采集方式：构建了由引擎内部状态和游戏特定策略驱动的**状态条件游戏智能体**，自动生成多样化玩家-boss 交互；引擎状态仅用于数据收集，推理时不可用。

## 6. 论文的主要结论与发现

- WorldMind 是首个游戏世界模型，使 NPC 行为成为交互式世界建模中的**显式、状态接地**的决策过程。
- 四层解耦设计在功能上分离、在反馈上耦合：生成结果会更新状态，从而影响后续 NPC 决策，实现闭环响应。
- L1 在三个游戏上实现了可靠的 boss-玩家几何重建，且紧凑状态保留了绝大部分决策相关信息。
- L2 的决策过程受到技能机制描述的强烈影响：移除或交换描述会显著改变首 skill 选择，在交换条件下模型更倾向于跟随迁移后的机制，而非固定技能标识。
- 全系统闭环评估中，WorldMind 在约 **70% 的成对比较**中被 LLM 评委偏爱，且在动作有效性和长时程序列契合度上均优于两个基线。
- 该方法支持 Direct Control 和 Director Control，二者在同一框架内工作，同时保持低速玩家控制和高级交互指令能力。
- 跨游戏泛化实验表明，L2 部分保留了跨游戏状态敏感性和机制接地能力，但紧凑状态重建需要目标域适配。

## 7. 优点

- **显式解耦接口**：将状态理解、决策、控制和生成分离，解决了现有模型中 NPC 行为缺少状态接地决策接口的问题。
- **闭环交互设计**：生成结果回流到理解层，使 NPC 行为能响应视觉后果和历史动作，而非开环执行固定序列。
- **统一控制模式**：同时支持玩家直接控制和导演级高层指令，扩展了交互式世界建模的应用场景。
- **机制接地的决策**：通过自然语言技能描述和冷却信息，使 LLM 能基于游戏机制推理合法且战术合理的动作，而非简单模仿历史数据。
- **大规模数据集与自动化采集**：BOSS-140K 提供超过 200 小时、多游戏、丰富的内部状态监督；状态条件智能体自动生成多样化交互，减少人工采集偏差。
- **实时性**：通过蒸馏将生成器加速到约 20 FPS，为实时交互展示提供了基础。
- **评估设计相对公平**：全系统对比使用相同 Wan 2.2 骨干和训练语料，突出了 NPC 行为产生方式的差异。

重建的跨域适配、L2 在目标游戏上的战术质量以及 L4 生成一致性均缺乏系统验证；跨游戏泛化目前主要停留在 L2 的机制跟随层面，尚未证明完整 WorldMind 闭环能在新游戏上稳定工作。

- **决策可靠性与约束检查仍较薄弱**：L2 的合法性检查主要基于冷却状态副本，只能过滤冷却不满足的技能，无法验证技能在空间距离、战斗阶段、资源条件或目标选择等方面是否真正可执行。LLM 仍可能生成看似合法但实际不可用的动作。
- **状态估计的闭环误差未分析**：L1 的几何分支在训练时依赖引擎标注，推理时仅依赖 RGB 帧和 boss 身份，存在明显的输入分布差异；论文没有报告闭环长时程 rollout 下几何误差是否会累积，并导致 L2 决策质量逐步退化。
- **蒸馏带来的视觉质量与一致性损失未评估**：约 20 FPS 的推理速度由蒸馏获得，但没有对比蒸馏前后生成视频的视觉质量、运动一致性或 NPC 动作保真度，也没有消融蒸馏阶段对最终闭环指标的影响。
- **数据覆盖与行为多样性仍有限**：BOSS-140K 仅涵盖 3 个游戏、14 个 boss，且主要为 2D 或 2.5D 视角；状态条件智能体采集策略虽然多样，但仍可能系统性地限制玩家-boss 交互空间，无法覆盖复杂 3D 导航、多人协作或开放世界场景。
- **端到端系统开销与实时性说明不足**：论文只给出生成层约 20 FPS 的近似值，未测量 L1 几何编码、L2 LLM 决策和 L3 提示组织的完整链路延迟，也未说明该速度是在何种硬件条件下获得，难以判断实际部署可行性。
