## 摘要
游戏角色不应在每次对话前都重新读取其完整生命历史。然而，对于本地部署的语言模型角色，修改少量记忆就可能使一个长的可复用前缀失效。由此产生的准备成本会与前台对话以及其他角色的维护相竞争。当对话为游戏定义的动作和价值判断提供输入时，这一点尤为重要：对物品归属或转移是否已经发生的流利但错误的陈述，可能污染本应确定性的规则输入。我们在一个量化的 Qwen 混合循环-注意力模型中研究长生命周期游戏 NPC 的增量记忆维护。我们的运行时移除已被取代的注意力 KV 条目，在真实序列尾部计算替换记录，并保留持续存在的循环状态和未更改的 KV。现有本地实验结合了多更新对话重放、固定输入放置消融和注意力诊断。独立块组合削弱了以查询为条件的记忆选择，而没有出现统一的块初始注意力坍缩。真实尾部更新在八个脚本化维护轮次中保留了重要的当前状态和历史绑定；一个放置案例在三次重建中恢复了完整补充数量，而保留槽位的替代方案则重复出现双重扣除错误。仅靠注意力分布接近度无法解释这些语义差异。这些结果促使我们将角色的推理状态视为一种需维护的、依赖于历史的资源，而不仅仅是对其最新记忆文本的一次性编码。

## Abstract
A game character should not have to reread its entire life before every conversation. For locally deployed language-model characters, however, revising a few memories can invalidate a long reusable prefix. The resulting preparation cost competes with both foreground dialogue and the maintenance of other characters. This matters especially when dialogue feeds game-defined actions and value judgments: a fluent but incorrect account of who owns an item, or whether a transfer has already happened, can corrupt the input to otherwise deterministic rules. We study incremental memory maintenance for long-lived game NPCs in a quantized Qwen hybrid recurrent-attention model. Our runtime removes superseded attention KV entries, computes replacement records at the true sequence tail, and preserves the continuing recurrent state and unchanged KV. Existing local experiments combine multi-update dialogue replays, fixed-input placement ablations, and attention diagnostics. Independent block composition weakens query-conditioned memory selection without a uniform chunk-initial attention collapse. True-tail updates preserve important current-state and historical bindings across eight scripted maintenance rounds; a placement case recovers the full-refill quantity in three reconstructions, while slot-preserving alternatives repeat a double-subtraction error. Attention-distribution proximity alone does not explain these semantic differences. The results motivate treating a character's inference state as a maintained, history-dependent resource, rather than only a disposable encoding of its latest memory text.

## 1. 论文的核心问题与整体含义

- **研究动机**：本地部署的语言模型游戏角色，在每次对话前若重读其全部生命历史，会产生高昂的准备成本。更关键的是，修改少量记忆会使原本可复用的长前缀失效，迫使系统重建整个上下文。
- **问题本质**：准备成本与前台对话、其他角色的维护相互竞争，尤其在共享本地加速器上尤为突出。当对话输出用于驱动游戏规则（如物品归属、转移是否已发生）时，流利但事实错误的叙述会污染确定性规则输入。
- **整体含义**：本地长生命周期游戏 NPC 需要把推理状态视为一种**需持续维护的、依赖于历史的资源**，而不是仅仅对最新记忆文本的一次性编码。全文围绕“如何在不重建整个上下文的前提下，增量维护不断演化的角色记忆”展开。

## 2. 论文提出的方法论

- **核心思想**：在混合循环-注意力模型中，保留**持续存在的循环状态**，移除被取代记录的**直接 KV 条目**，并在**真实序列尾部**计算替换记录，从而避免重新编码未更改的记录。
- **形式化表示**：
  - 记忆更新：`M_{t+1} = (M_t \ D_t) ∪ U_t`，其中 `M_t` 为维护步骤 t 后的活跃记录集，`U_t` 为新增/更新记录，`D_t` 为被取代记录。
  - 状态更新：`¯A_t = A_t \ A_t[D_t]`，然后 `(A_{t+1}, R_{t+1}, p_{t+1}) = F_θ(U_t; ¯A_t, R_t, p_t)`，其中 `A_t` 为注意力缓存，`R_t` 为循环和卷积状态，`p_t` 为下一个序列位置 ID。
- **关键设计**：
  - **分离两种状态生命周期**：显式 KV 记录的生命周期与持续循环状态分离，删除记录仅移除其直接未来注意力访问，**不能擦除其间接历史影响**。
  - **真尾更新**：替换记录在真实新尾部位置计算，绝不将更新键旋转回旧记录位置，避免 Rotary Position Embedding 带来的位置依赖问题。
  - **删除产生空洞**：被删除位置成为“洞”，不填充 dummy KV；位置光标单调递增，与活跃 KV 占用分离。
  - **运行时记录寻址**：每个活跃记录具有稳定语义标识符和 token 跨度映射，运行时验证删除范围、移除被取代条目、保留无关 KV 而不重放其 token。
  - **不训练模型权重**：方法完全基于现有冻结模型权重的运行时干预。

## 3. 实验设计

- **场景与数据集**：
  - 合成游戏角色 **Lin Qingyao** 与玩家角色 **Yin Xu**，发生在中国奇幻背景下。
  - 早期实验使用 **34 个记忆组、123 个保留细节**，记忆区域 13,250 tokens，加上 1,699 tokens 公共头部上下文。
  - 后续场景混合了记忆记录和实体认知记录，测试物品效果、库存、目的地、亲属关系等变化。
  - **不是标准 benchmark**，而是脚本化的维护场景和受控 replay。
- **对比方法**：
  - **Dense refill**（密集重填）：从头顺序读取当前文本。
  - **Independent composition**（独立组合）：每个记忆组从同一公共头部独立计算，然后组装 KV。
  - **Fresh gapped prefill**（新鲜间隔预填充）：顺序读取文本，但记录之间保留 10K 序列位置间隔。
  - **Slot-preserving maintenance**（保留槽位维护）：在因果工作尾部推进循环状态，但用偏移到原始槽位的 RoPE 位置计算替换 Q/K，然后重新标记缓存位置。
  - **True-tail maintenance**（真实尾部维护）：更新记录获得真实新尾部位置。
  - **Tail-and-relocate**（尾部计算后旋转）：用尾部位置 RoPE 计算更新，再将存储键旋转回旧位置。
- **评估方式**：
  - 分为**端到端轨迹**（多轮对话）与**固定输入诊断**（冻结模块请求）两类。
  - 使用**注意力测量**：在 full-attention 层仪表化实际 query/key/mask，用 float32 参考 softmax 重建注意力，平均最后 8 个 query token 的注意力。
  - 关键指标：注意力分布、有效组数（熵散度）、token 分布总变差距离、行为结果（如物品数量、参与者绑定）。
- **主要实验 cohort**：
  - 独立组合 vs 全量重填（两次对话回合，共享首轮请求）。
  - 五更新注意力对比（相同最终 38 组文本，四个探针）。
  - 八更新混合记录 replay（25 条记录维护为 24 条，9 轮对话）。
  - 10K 放置探针（三个冻结模块请求：对话、草药编译、编译门控）。
  - 尾部/重定位消融（三次重建）。
  - 长视野提示探针（三个冻结模块输入，改变最终任务）。

## 6. 论文的主要结论与发现

- **独立组合削弱选择性寻址**：在明确的焦点 ID 探针下，独立组合使指定记忆组的注意力从 57.4% 降至 21.5%，有效组数从 18.3 升至 33.2（共 34 组），但未发现 EPIC 所述的均匀块初始坍缩。端到端失败案例：将“今天黎明发现”错误表述为“昨晚发现”。
- **真实尾部维护保留相关旧记录和修订记录**：五更新注意力对比显示，维护状态与全量重填在旧记录注意力上相近（39.40% vs 40.08%），八轮脚本化维护后仍能正确绑定重要当前状态与历史状态，如“过去的温情是真的，现在的危险也是真的”。
- **更新放置改变状态-事件绑定**：草药数量案例中，密集重填和新鲜间隔预填充均编译出“两株”草药，而保留旧槽位维护错误地编译出“一株”（重复扣除已完成的转移）；真实尾部更新三次重建全部正确输出“两株”，尾部计算后旋转键回旧位置则三次全部错误。
- **注意力分布相似性不能保证语义正确性**：某些情况下注意力分布距离更大但答案正确，距离更小却出现事实绑定错误；注意力热图不能作为语义忠实度的替身。
- **提示引导恢复无需重建记忆**：在同一维护状态中，改变任务框架（先建立理解再推导情感）可以纠正事件参与者绑定错误，而未重建或修复前缀。
- **更新成本随变更记录而非整个前缀**：8 次混合记忆修订总计 3.48 秒，而估计的重复重建需 81.6 秒，约 **23.5 倍加速**；首次构建约 10.2 秒。

## 7. 优点

- **实现层创新**：在真实混合循环-注意力模型上实现了直接 KV 删除和循环状态保留的运行时机制，无需修改权重。
- **问题定位清晰**：将记忆维护与游戏规则治理、资源核算、动作绑定联系起来，强调了记忆错误的机械后果。
- **实验设计严谨**：区分端到端轨迹与冻结输入诊断，使用固定模块回放隔离变量；注意区分注意力分布距离与语义正确性。
- **诚实报告局限**：明确声明删除不等于遗忘、注意力诊断不是因果归因、案例研究不是基准；给出了下游错误和不完美之处。
- **成本量化**：提供了具体时间测量和校准速度比，展示增量维护的实用价值。
- **可复现性**：提供了数据 snapshots 和实验 ID，方便追溯。

## 8. 不足与局限

- **规模有限**：仅在单台笔记本、单模型、单一合成角色上运行，缺乏多角色、多模型、多硬件配置的评估。
- **缺乏统计算力**：三次重建是重复性检查，不是独立样本；没有概率性准确率或显著性检验。
- **与现有系统比较不完整**：未实现 CacheBlend、EPIC、HYPIC、LinearKV 等完整算法作为 baseline，仅做了简化的独立组合实验。
- **删除不等于遗忘**：循环状态和深层 KV 可能保留被删除记录的间接影响，方法不适合作为隐私或秘密删除的安全保证。
- **注意力解释的局限性**：注意力分布是描述性诊断，不能作为因果归因；使用的参考 softmax 与 fused CUDA kernel 可能有数值差异。
- **应用限制**：角色设定单一（中国奇幻背景），未覆盖更多元的对话和记忆场景；没有完整游戏实现或用户研究；端到端轨迹中存在下游错误（如擅自发明修为等级、丢失白天限制）。
- **位置轨迹未解决**：位置 ID 单调递增，长期运行会遇到位置编码极限，论文未提出解决方案。
- **实验充分性**：作者承认现有证据是案例研究和诊断，而不是全面评估；多角色总体评估、更长维护、对抗性修订等仍是未来工作。
