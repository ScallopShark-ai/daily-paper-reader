## 摘要
虽然许多视频游戏环境（VGEs）在推动强化学习（RL）方面发挥了关键作用，但开发新的VGE或修改现有VGE以支持新功能一直是一个需要大量手工编码的繁琐过程。在此我们提出 PlayTrain，一个 RL 框架，它结合了大型语言模型（LLMs）从最少的人工提示稳健生成 JavaScript（JS）游戏的能力，以及一个可以在标准“gym”环境中运行任何 JS 游戏的高效流水线。近期的 LLM 不仅特别擅长编写 JS 代码，而且 JS 格式还允许用户轻松游玩生成的 VGE，同时 PlayTrain 使我们能够在完全相同的游戏上训练 RL 智能体。我们展示了 PlayTrain 的多个用例，包括用简单的 JS 克隆著名的 Atari 和 ProcGen 游戏，其中 PlayTrain 在单个 GPU 节点上以每秒超过 100 万次智能体决策的速度端到端训练基于像素的智能体；以及创建它们的修改版本（例如，支持新的测试集、程序化生成逻辑或游戏动态）。通过 PlayTrain，我们重新构想了 RL VGE 开发：我们所需要的只是一个通过 LLM 生成和修改的单一 JS 文件。我们讨论了 PlayTrain 开辟的有前景的未来 RL 研究方向。

## Abstract
While many video-game environments (VGEs) have played crucial roles in advancing reinforcement learning (RL), developing novel VGEs or modifying existing ones to support new features, has been a laborious process requiring extensive hand-coding. Here we present PlayTrain, an RL framework that combines the abilities of large language models (LLMs) to robustly generate JavaScript (JS) games from a minimal human prompt, and an efficient pipeline that can run any JS game in a standard 'gym' environment. Not only are recent LLMs particularly good at writing JS code, but the JS format also allows users to easily play generated VGEs, while PlayTrain enables us to train RL agents on the exact same games. We demonstrate multiple use cases of PlayTrain, including cloning well-known Atari and ProcGen games in simple JS, where PlayTrain trains pixel-based agents end-to-end at over 1M agent-decisions per second on a single GPU node; and creating modified versions thereof (e.g., that support novel test sets, procedural generation logics, or game dynamics). Through PlayTrain, we reimagine RL VGE development: all we need is a single JS file, generated and modified through an LLM. We discuss promising future RL research directions that PlayTrain unlocks.

## 1. 论文的核心问题与整体含义

- **问题背景**：强化学习（RL）的发展高度依赖视频游戏环境（VGE），但传统 VGE 的开发与修改需要大量手工编码，成本高、迭代慢，难以灵活适应新的研究需求。
- **核心矛盾**：理想的 RL 游戏环境应同时具备 **效率**、**复杂度**、**可适应性**和 **可玩性** 四个特性，但现有主流框架往往只能兼顾其中部分。例如，Atari/ProcGen 固定了游戏集合，GPU 移植类环境难以修改，而基于浏览器的 JS 游戏虽可玩、易修改，却因浏览器开销导致交互速度极慢。
- **整体含义**：PlayTrain 提出一种新范式：用大语言模型（LLM）从简单提示生成单个 JavaScript 文件作为游戏环境，并在无浏览器的自定义后端中高效运行，从而将“概念 → 环境 → 训练 → 人类测试”的全流程压缩到近乎“只需一个 JS 文件”。这重新定义了 RL 环境开发的效率和灵活性边界。

## 2. 论文提出的方法论

- **LLM 生成与修改 JS 游戏**：
  - 从简短的自然语言规范（游戏名、机制、参考链接等）出发，使用 Gemini 3.1 Pro 生成单个自包含的 JavaScript 文件。
  - 生成文件必须符合固定 RL 生命周期接口：`setup()`、`draw()`、`resetGame(seed)`、`getGameState()`，以及确定性随机数生成器 `mulberry32(seed)`。
  - 采用自动验证脚本检查 Gymnasium API 合规性、确定性（相同种子和动作序列产生完全一致的观察）以及观察/奖励/终止条件的合理性。
  - 支持通过自然语言反馈进行**迭代精炼**和**变体生成**（参数变体、结构变体、视觉/主题变体等）。

- **高效无浏览器后端**：
  - **JS 引擎**：使用 QuickJS（C 库形式），直接嵌入到训练进程，避免浏览器和 Node/V8 的额外开销。
  - **p5.js 替换层**：用 C++ 重写 p5.js 的 40 个绘图/输入命令，使游戏代码中的 `ellipse()`、`fill()` 等调用直接进入编译后的原生代码。
  - **光栅化器**：用 Rust 编写自定义光栅化器，将绘图命令直接渲染为 `64×64×3` RGB 观察帧，写入共享内存缓冲区，不做全尺寸渲染或降采样。
  - **线程池设计**：借鉴 EnvPool，在单个进程内用多线程运行多个环境实例，所有线程共享观察缓冲区，避免进程间通信开销。
  - **确定性保证**：控制时钟、随机数生成器和渲染算术（自实现 `sin`/`cos`），确保跨机器可复现。

- **训练接口与算法**：
  - 默认动作空间为 `Discrete(8)`（NOOP、LEFT、RIGHT、UP、DOWN、D、LEFT+D、RIGHT+D），后端将动作转换为键盘状态。
  - 实现了 IMPALA（带 V-trace）和 PPO 两种训练器；IMPALA 使用**双缓冲**（一组环境步进时，另一组进行 GPU 推理）提升吞吐。

  - LLM 可低成本、快速生成可玩的 JS 游戏及变体；6 个示例共耗时 34.4 分钟、费用不到 1 美元。

## 7. 优点

- **创新性整合**：将 LLM 代码生成能力与高性能 JS 执行后端结合，首次实现“提示→单文件 JS 游戏→高效 RL 训练”的完整闭环。
- **后端设计精巧**：
  - 用 QuickJS 嵌入进程，消除浏览器和跨进程通信开销。
  - C++ 重写 p5.js + Rust 光栅化器，使绘图调用直接写入观察缓冲区，速度提升显著。
  - 共享内存线程池实现近线性扩展，超越 EnvPool 在 ProcGen 上的表现。
- **确定性保证**：自实现数学函数、固定时钟与 RNG，确保可复现，这对科学实验至关重要。
- **真实可玩性**：同一 JS 文件既可在浏览器中由人类游玩，也可用于训练 RL 智能体，无缝桥接认知科学与 RL。
- **低成本与易用性**：生成变体成本极低（< $1），界面支持自然语言精炼，显著降低环境开发门槛。
- **开源与可验证性**：提供代码仓库和在线平台，所有生成游戏可公开访问；实验配置记录详细，便于复现。

## 8. 不足与局限

- **游戏复杂度受限**：
  - 目前只能生成几百行的单文件 2D 游戏，无法支持现代 3A 级或大规模 3D 游戏（如《塞尔达传说：旷野之息》）。
  - 视觉风格被限制为 ProcGen/Atari 式简单图形，以保证 64×64 观察下的可读性与训练效率。
- **速度退化风险**：
  - 游戏逻辑或绘图指令过多时，吞吐显著下降。例如 `qbert.bigmap` 仅 39k SPS，远低于套件平均 0.35M；`miner` 单步 75% 时间花在 787 次绘图调用上。
  - 个别克隆（`chaser`、`climber`）仍比原版 ProcGen 慢，说明并非所有游戏都能从该框架获益。
- **依赖 LLM 能力**：
  - 生成质量与保真度取决于底层 LLM 能力，当前模型可能无法一次性生成复杂或高度一致的游戏；需要多轮精炼。
  - 克隆游戏与原版在视觉和细节上可能存在偏差，缺乏定量保真度评估。
- **实验评估局限**：
  - 人类实验样本量小（20 人），游戏数量有限（8 个），且游戏时长仅 100 秒，可能低估人类学习潜力。
  - 未进行大规模统计显著性检验；RL 训练曲线仅展示 3 seeds 的均值/范围，未报告置信区间外的稳健性分析。
  - 与现有 GPU 加速环境框架（如 JAX 系、CuLE、Brax 等）的对比不够全面。
- **3D 支持尚未完成**：论文提到 3D 渲染正在开发中，目前框架主要面向 2D 环境。
- **动作空间与观察标准化限制**：默认统一为 Discrete(8) 和 64×64 RGB，虽可配置，但可能不适用于需要连续控制或更高分辨率观察的任务。
