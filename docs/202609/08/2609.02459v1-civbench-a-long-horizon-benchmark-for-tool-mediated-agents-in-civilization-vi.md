## 摘要
我们提出了 CivBench，一个通过模型上下文协议（MCP）在长时程、工具介导的环境中评估语言模型智能体的开源基准。单个对局跨越 300 多个轮次，并在庞大的动作空间中产生数千次工具调用，要求智能体在部分可观测条件下持续进行规划、状态监测和执行。该环境提供 76 个 MCP 工具和一个叙述层，将视觉游戏状态转换为结构化文本。
我们使用 CivBench 在 23 次有效运行中对四个模型系列的行为进行了刻画。样本为试点，而非模型排名：在这一规模下，聚合结果无法可靠地区分模型。相反，我们引入了两个由环境可测量的接口级指标：主动监测率（PMR），衡量智能体是否主动查询潜在的策略状态；以及 RAG@10，衡量结构化规划反思中声明的承诺是否在后续十个轮次内得到执行。
在共享行动手册协议下，跨多次运行我们观察到两种一致模式。智能体对可用但需要显式查询的战略相关状态的监测不足：尽管行动手册建议每 20 个轮次查询一次胜利进度，智能体实际每 30 到 75 个轮次才查询一次；在 20 次可检测的失败中，有 7 次未能在游戏结束前的 20 轮警告窗口内进行查询。智能体还经常未能执行其自身规划反思中声明的近期承诺（各模型的 RAG@10 介于 48.2% 到 65.8% 之间）。这两种模式在具备工具访问和明确指导的情况下依然出现，我们将其解释为指令下的偏差，而非能力缺失。
我们在 https://github.com/lmwilki/civ6-mcp 发布环境、场景、日志、指标和分析流程。

## Abstract
We present CivBench, an open-source benchmark for evaluating language model agents in long-horizon, tool-mediated environments through the Model Context Protocol (MCP). A single episode spans 300+ turns and produces thousands of tool calls over a large action space, requiring sustained planning, state monitoring, and execution under partial observability. The environment exposes 76 MCP tools and a narration layer that converts visual game state into structured text.   We use CivBench to characterise agent behaviour across four model families in 23 admissible runs. The sample is a pilot, not a model ranking: aggregate outcomes do not reliably discriminate models at this scale. Instead, we introduce two interface-level metrics that the environment makes measurable: Proactive Monitoring Rate (PMR), capturing whether agents actively query latent strategic state, and RAG@10, capturing whether commitments stated in structured planning reflections are executed within ten subsequent turns.   Across runs we observe two consistent patterns under a shared playbook protocol. Agents under-monitor strategically relevant state that is available but requires explicit querying: despite playbook guidance to query victory progress every 20 turns, agents do so only every 30 to 75 turns, and in 7 of 20 detectable defeats they failed to query within the 20 turn warning window before game end. Agents also frequently fail to execute near-term commitments stated in their own planning reflections (RAG@10 between 48.2% and 65.8% across models). Both patterns arise despite tool access and explicit guidance, and we interpret them as deviations under instruction rather than absences of capability.   We release the environment, scenarios, logs, metrics, and analysis pipeline at https://github.com/lmwilki/civ6-mcp

- **核心问题**：
  - 缺乏一个能够在 300+ 回合、数千次工具调用的真实长时程环境中，系统测量智能体“注意力分配”和“计划执行一致性”的基准。
  - 智能体是否主动检索潜在关键状态？是否将自己声明的短期计划转化为后续动作？
- **整体含义**：论文提出 CivBench，不是用于模型排行榜，而是一个可复现的基准与测量协议，用于揭示长时程工具介导智能体在“信息可见但未主动查询”和“计划已声明但未执行”两类行为偏差。

## 2. 论文提出的方法论

- **核心思想**：
  - 通过模型上下文协议（MCP）将语言模型智能体连接到《文明 VI》游戏，暴露 76 个工具。
  - 通过“叙述层”将视觉游戏状态转换为结构化文本，但只有智能体显式查询的状态才会进入上下文，从而区分“信息不可用”与“信息可用但未被检索”。
- **关键技术细节**：
  - **MCP 工具集**：覆盖状态查询（27 个）、单位行动（10 个）、城市管理（9 个）、外交（7 个）、治理（10 个）、宗教与文化（5 个）、游戏生命周期（8 个）等，共计 76 个工具。
  - **叙述层**：共 29 个函数将游戏状态转为结构化文本，并设计“感知意识”提示，例如超 500 金币建议部署、扩张基准（T40 应有 2 城等）、每 20 回合检查 `get_victory_progress` 等。
  - **共享行动手册（playbook）**：规定每回合结构、检查点和五字段日记（tactical / strategic / tooling / planning / hypothesis），用于标准化交互结构，同时将工具选择和优先级留给智能体。
- **核心指标定义（文字说明）**：
  - **PMR（主动监测率）** = 战略监测工具调用数 / 所有非基础设施工具调用数。基础设施调用（如 `end_turn`）被排除；衡量智能体工具预算中有多少用于维护全局视图。
  - **RAG@K（反思–行动差距）** = （完全执行数 + 0.5 × 部分执行数）/ 总承诺数，K=10。承诺从规划反思中提取，在 10 回合窗口内判定是否执行、部分执行或未执行。

  - 有效运行（admissible runs）：共 23 局，Ground Control 19 局，Snowflake 4 局；Cry Havoc 未纳入报告。
- **基准与对比对象**：
  - 对比四个模型家族：Claude Opus 4.6（n=8）、GPT-5.4（n=8）、Gemini 3.1 Pro（n=6）、Kimi K2.5（n=1，探索性）。

- **评估方式**：

## 6. 论文的主要结论与发现

- **聚合结果不足以区分模型**：23 局中仅 3 次胜利，全部为 Ground Control 的科技胜利；胜/负和归一化分数均无统计显著差异。
- **发现一：传感器效应（sensorium effect）**：
  - 智能体对需要显式查询的战略状态监测严重不足。
  - 尽管行动手册建议每 20 回合检查一次胜利进度，智能体实际每 **30–75 回合**才查询一次。
  - PMR 总体低，介于 **0.96%–2.13%** 的非基础设施调用；胜利监测仅占 **0.05%–0.29%**，对应每局 3.7–10.0 次 `get_victory_progress` 调用。
  - 在 20 次可检测失败的败局中，有 **7 次**未能在结束前 20 回合警告窗口内查询胜利进度。
  - PMR 在终局并未系统性上升，表明这是持续的注意力分配选择而非临时的上下文限制。
- **发现二：反思–行动差距（reflection-action gap）**：
  - 各模型的 RAG@10 介于 **48.2%–65.8%**，即大量自我声明的短期承诺在 10 个回合内未执行。
  - 例子包括“在新城市建校园”“建立第二座城市”“检查胜利进度”等。
  - 三个模型家族（Claude、GPT、Gemini）的 bootstrap 置信区间重叠，差异不显著。
- **总体解释**：这两种偏差在工具可用、指令明确的情况下仍然出现，属于“指令下的行为偏差”，而非能力完全缺失。

## 7. 优点

- **环境设计创新**：
  - 使用 MCP 而非传统 Gymnasium 接口，更接近生产级工具使用场景。
  - 叙述层实现“可控可观测性”，明确区分信息可用性和主动检索，直接暴露注意力分配问题。
- **指标贡献**：
  - PMR 和 RAG@10 是接口级别的行为指标，能从轨迹中直接量化监控和计划执行，无需仅依赖最终结果。
- **长时程覆盖真实**：
  - 单局 300+ 回合、数千次工具调用，涵盖多领域决策（经济、科技、文化、军事、外交、空间、时间）。
- **可复现性与透明度**：
  - 发布环境、场景、日志、指标、分析脚本；提供模型访问窗口、端点、配置、种子等细节。
  - RAG 标签经过人工验证（κ=0.879），提高了可信度。
- **分析深度**：
  - 通过 ICC 检验、滚动窗口 PMR、里程碑城市数等展示了统计证据，而非仅靠主观观察。
  - 将欠监测与具体失败（错过警告窗口）联系起来，提供了机制性解释。

## 8. 不足与局限

- **样本量与统计功效**：
  - 仅 23 局，模型家族间样本不均（Kimi 仅 1 局），无法进行可靠的模型排名；许多结论是描述性的。
  - 只有大效应才有统计功效，较小的模型差异可能无法被检测。
- **实验覆盖与基线缺失**：
  - 缺少随机或脚本基线，无法提供行为指标的“下限”参照。
  - 没有行动手册自由基线（playbook-free）的正式对比；此类基线完成率仅 21%，但其对照价值有限。
  - Cry Havoc 场景被排除，Snowflake 只有 4 局，场景级结论为描述性。
- **混淆与偏差风险**：
  - **行动手册混淆**：所有行为都在共享行动手册引导下产生，偏差应解释为“指令下的偏差”，不能直接推及无引导的自主行为。
  - **训练数据污染**：策略知识可能出现在模型训练数据中，难以区分知识与执行能力。
  - **RAG 测量依赖 LLM 标注**：用于标注的 Claude Haiku 4.5 与被评估的 Claude Opus 4.6 同家族，虽作者指出 Claude 得分最低、未表现同家族偏倚，但风险仍存在。
- **环境与可扩展性限制**：
  - 《文明 VI》为商业授权，用户需拥有游戏副本，且 FireTuner 协议仅支持单连接，限制多智能体设置。
  - 游戏版本、DLC、操作系统、模型更新和随机性都会影响可重复性。
- **结论外推性**：
  - 所有观察到的胜利均出现在 Ground Control；其他地图、难度或胜利限制下的行为可能不同。
  - PMR 和 RAG 仅衡量特定协议下的行为，不应视为智能体能力的完整刻画。
