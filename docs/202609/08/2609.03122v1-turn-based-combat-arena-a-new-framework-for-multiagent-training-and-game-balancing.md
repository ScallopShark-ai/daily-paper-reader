## Abstract
This paper is the first in a series on Turn-Based Combat Arena, a configurable framework for turn-based strategy games designed to support the efficient training and evaluation of machine learning agents. The proposed framework enables flexible modification of game rules and parameters, allowing rapid experimentation across diverse scenarios. Its architecture is optimized for high-throughput simulation, supporting tens of thousands of games per second and enabling the storage and processing of billions of gameplay records on a single machine. The problem of balancing the game, and particularly the parameters of game units, is investigated in detail. We evaluate several optimization approaches and show that multiple methods converge to comparable solutions, suggesting robustness in identifying balanced game configurations. These results indicate that the framework can serve as a practical platform for both game design analysis and agent training.

## 2. 论文提出的方法论

### 2.1 TBCA 游戏规则与可配置机制

- 游戏几何：矩形 N×M 竞技场（本文取 N=M=20），正交相邻距离为 1，对角相邻距离为 1.5；可选复杂地形，但本文仅考虑平坦拓扑。
- 双方队伍：A、B 两队，各 T 个单位（本文 T=8），初始位于最左列与最右列；单位类型可确定性或随机生成，本文主要采用随机团队组成模式。
- 单位类型：五种类型 Light (L), Heavy (H), Fast (F), Short-Range (SR), Long-Range (LR)。
- 单位参数：
  - 健康值 H（本文统一取 10，死亡即健康为 0）；
  - 攻击等级 A（0–30）；
  - 防御等级 D（0–30）；
  - 攻击范围 AR；
  - 移动点 MP。
- 伤害机制：  
  DM = floor(DM₀ · A(A, D) · R)  
  其中 DM₀ = H / N 为基础伤害；A(A, D) = 1 + (A − D)/50；R = 1 + α · rnd(−1, 1) 为随机因子，本文 α=0.1，rnd 服从均匀分布。
- 反击规则：目标存活且攻击者在其攻击范围内时可反击，反击伤害为直接攻击的一半。
- 移动优先级：由单位移动点 MP 决定，MP 越高越先行动；相同 MP 的单位随机排序。每回合单位可跳过、移动、攻击，或移动后再攻击，但不能多次动作。
- 平局规则：当“空闲”回合数超过可配置阈值时判定平局，避免无限循环。
- 状态空间复杂度：论文推导得到约 3.62 × 10⁶⁰，介于 Hex（10⁵⁷）与 Thurn and Taxis（10⁶⁶）之间，高于国际象棋（10⁴³）。

### 2.2 框架架构

- 战斗引擎：无状态设计，支持多线程并行运行，是高性能仿真的核心。
- 数据库：采用现代 OLAP 列式存储（本地 DuckDB），可高效处理 3–4 亿条记录，占用约 100 GB 磁盘。
- 内存暂存层：弥补列式存储频繁更新能力弱的缺陷，先积累战斗统计，再按计划批量写入数据库。
- Battle API：实时 WebSocket API，向 AI 智能体发送当前战斗状态与可用目标/移动位置，接收 Skip / Attack / Move 动作及可选标签，方便外部 AI 集成与策略元数据记录。
- 内置规则型玩家：提供多种基于规则的战斗智能体，可通过相同 API 与外部 AI 玩家互换。

### 2.3 游戏平衡指标

- 同单位队配对指标：构建同类型单位相互对战的 5×5 击杀/死亡矩阵，定义 k²、k²₀、d²、d²₀ 等归一化均方误差作为潜在损失函数。
- 半随机队配对指标：每队包含五类单位各一个，其余单位为某一特定类型，形成 k′²、k′²₀、d′²、d′²₀ 等指标，用于捕捉单位间协同效应。
- 战斗级指标：胜利时剩余单位数 n 的 MSE σₙ；总行动数 a 的变异系数 εₐ = σₐ/ā。
- 单位类型特定指标：
  - 生存率 sᵢ = Sᵢ / Nᵢ，及其 MSE σₛ；
  - 胜利影响 wᵢ = 获胜队伍中类型 i 单位的初始数量，及其 MSE σ_w。

### 2.4 优化方法

- 优化参数：5 种单位各自的 A、D，共 10 个离散整数参数，每个取值 0–30。
- 战术参数固定为：  
  L(1,12), H(1,5), F(1,17), SR(7,5), LR(17,2)，对应 (AR, MP)。
- 基础伤害 DM₀ = H / 3.5，设计时考虑最慢近战单位抵达远程单位前不被消灭的合理概率。
- 优化算法：CMA-ES（协方差矩阵自适应进化策略），将离散参数视为连续变量优化，最终评估时四舍五入为整数。

## 6. 主要结论与发现

- TBCA 状态空间复杂度约 10⁶⁰，可通过调整健康值、单位类型数、单位数等参数灵活调节游戏复杂度。
- 不同损失函数得到的最优 A、D 参数虽有差异，但存在一致趋势：F 与 SR 攻击宜高，LR 攻击宜低；SR 防御宜低，H 防御宜高。
- 基于胜利影响 σ_w 与基于半随机团队配对的 k′²、k′²₀ 平衡结果具有较高一致性，且均能产生较公平的胜利影响值。
- 严格击杀与死亡平衡（k²₀）的最小值仍然较高（0.462），说明该平衡目标不可完全实现。
- 所有单位类型生存率不能同时平衡；基于 σₛ 优化的参数与其他方法差异最大，且产生极端参数。
- 战斗级指标 σₙ 与 εₐ 不宜直接作为损失函数，但可作为平衡状态的指示器：数值过高说明游戏可能不平衡。
- 推荐：先合理设计伤害函数与战术参数，再用半随机团队配对指标或胜利影响 σ_w 优化单位的攻击/防御参数；其中 σ_w 更少依赖半随机团队组成假设，是更优损失函数。

## 7. 优点

- 框架设计具有高吞吐、无状态并行仿真能力，适合大规模强化学习数据生成。
- 灵活可配置的规则集与状态空间复杂度可调机制，使平台适用于从简单到复杂游戏的研究。
- 完整的数据管道：内存暂存、列式数据库、WebSocket API，便于外部 AI 集成和大规模对局记录分析。
